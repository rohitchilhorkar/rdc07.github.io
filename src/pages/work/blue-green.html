Blue-Green release CLI

One command for production releases that runs 15+ validation and deployment steps, the same way every time.

  • 15+validation and deployment steps automated
  • Python · Bashvalidation tooling
  • Terraformand Ansible for the AWS infra underneath

The idea

Blue-Green keeps two environments. The new release goes to the one that is not serving users, gets checked, and only then takes over. If something is wrong, the old one is still there.

What was built

  • A CLI that wraps the release into one command and runs 15+ validation and deployment steps in order.
  • Around it, Python and Bash tooling for deployment validation and IAM permission-boundary troubleshooting.
  • Infrastructure underneath provisioned with Terraform and Ansible on AWS.

Why it matters

Manual release checklists drift. Putting the steps in a tool makes every production release follow the same path, and makes a skipped check much harder.
