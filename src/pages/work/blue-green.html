Blue-Green release CLI

Zero-downtime upgrades for Teamcenter X, Siemens' cloud PLM, with one CLI that runs 15+ post-deployment checks on every release.

  • 0downtime during version upgrades
  • 15+post-deployment checks automated
  • ~30 minof manual checking saved per release

The idea

Blue-Green keeps two environments. The new Teamcenter X version goes to the one that is not serving users, gets checked, and only then takes over. Users never see the upgrade happen, and if something is wrong, the old environment is still there.

What was built

  • Automated Teamcenter X version upgrades on a Blue-Green strategy, removing manual upgrade steps.
  • A CLI that runs 15+ post-deployment checks after every release, saving about 30 minutes of manual checking each time.
  • Around it, Python and Bash tooling for deployment validation and IAM permission-boundary troubleshooting.
  • Infrastructure underneath provisioned with Terraform and Ansible on AWS.

Why it matters

Manual release checklists drift. Putting the checks in a tool makes every production release follow the same path, and makes a skipped check much harder.
