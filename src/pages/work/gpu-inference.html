GPU inference on EKS, scaling from zero

Deployed the AI platform for a financial surveillance product on Amazon EKS. GPU nodes only exist while the models need them.

  • 3AI services: alert classification, deduplication, AI Assist
  • 0 → NNVIDIA GPU nodes, scaled by Karpenter
  • 0static AWS keys, IRSA everywhere

The setup

  • Two Karpenter node pools: a CPU pool for the application services, and an NVIDIA GPU pool that scales from zero.
  • GPU nodes are tainted, so only the LLM inference workload (Ollama serving Llama 3.1 and 3.2) is scheduled there. HPA scales the model servers.
  • Model storage on shared EFS; Milvus for vector search behind deduplication; RabbitMQ between services.
  • IRSA for every service account and Secrets Manager at runtime, so no static credentials in the cluster.
  • Shipped with Jenkins, Ansible, Helm and Terraform.

Why it matters

GPUs are the most expensive nodes in the cluster. Scaling the pool from zero and keeping everything else off it means paying for GPU time only when inference is actually running.
